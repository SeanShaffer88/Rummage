# Planning Module Contracts

Copyright 2026 Malikor; GPL-3.0-or-later, as the repository LICENSE. Native Lua 5.1 and existing WoW adapters only; no new dependencies, telemetry or import-time background operations.

`InventoryPlan:Capture(bags,bank)` creates private slot snapshots with explicit metadata knowledge. `Allocate(source,destination,wanted)` simulates full-link capacity, reserves destinations and computes signed carried-slot effects. Shared/overlapping slot regions are explicitly unsupported; disjoint bag-to-bag plans remain supported. `Forecast(kind,query)` is read-only and uses the actual canonical sale plan before filtering, never treating the query as an enabled junk rule.

`Restock:SetTarget(id,quantity)`, `Preview()`, `Execute(token)`, `Cancel()` own account-wide targets and current-character live-bank consent. The latest issued token is compared against a private deep snapshot; session, configuration, source/destination identity/count/locks, stack/family metadata and live deficit are revalidated. Execution composes the canonical Mover singleton and acknowledgement phases. Another carried acquisition shrinks or stops a pending movement; no later movement expands the original approved amount. Unknown carried quantities cannot authorize execution, while partially known bank totals are labelled lower bounds. Preview/forecast state is transient and never importable authorization.

`RuleDiagnostics:AnalyzeRules(optionalDraft)` reports all enabled matches, OR overlaps, classification provenance and canonical sale eligibility/cap/reserve effects from one independent plan snapshot. `Junk:Classify` preserves existing manual/rules/Scrap/poor precedence and records successful/fallback provenance. No diagnostic action changes inventory, rules or retained UI pools.

`VendorSession:Token()`, `Record(action,status,fact)`, `Summary()` consume private operation/session facts before public History notifications. Facts bind unique sale-ledger/operation identities; gross sales and confirmed buyback cost are distinct from wallet delta. Split staging and partial sales retain original operation identity so a temporary split removal is not an extra free slot. Current keep retention counts configured candidates once per item ID. Current/last summaries are transient, bounded and excluded from exports/profiles.

`Planning:Show(tab)` lazily composes the four native views with explicit confirmation for Restock only. Shared targets/current-character wording, Unknown/lower-bound quantities, clipped full-text tooltips and fonts 6..24 follow the approved mockup. Existing Tools is not refactored.

Verification: 146 native Lua cases (122 previous plus 24 planning groups), 19 offline publisher cases, real syntax/TOC and static packaging checks. Stateful oracles include target20/carried7/bank50 withdrawing13 via capacity8+5, eager/deferred split timing, metadata replacement, current deficit shrink, private consent mutations, bank/session/combat/cursor/callback interruption, conditional signed forecasts, OR/protection explanations, independent vendor facts and native layout geometry. Final gate exits, independent review and guard-mutation evidence are recorded in delivery artifacts. All new live-client checks remain Unperformed under the user's offline-only instruction.
