# Safe Inventory Tools: Interfaces And Verification

These modules use the existing Lua 5.1/WoW runtime with no additional addon dependencies. Copyright 2026 Malikor, GPL-3.0-or-later, as in the root LICENSE.

- `Junk:PreviewRule(query)` returns a preview or `nil,error`; it is read-only with respect to inventory, rules, favorites and reserves. `EnableRule(preview)` is a separate single-use action bound to that exact query. The preview shares the live bag planner, eligibility, reserve budgets and buyback batch cap with sales.
- `Junk:SetKeep(itemID,quantity)` validates positive finite integral IDs up to 2147483647 and whole quantities 0..1000000; zero removes. Reserves are account-wide, current carried bags only. A partial sale owns a bounded state machine and returns only a matching addon-owned cursor item on cancellation. No background timer remains after termination.
- `Buyback:Availability(historyID)`, `FromHistory(historyID)`, and the compatible `Junk:Buyback(nOrAll)` serialize exact signature requests. `AddSale` creates a persisted local ledger ID; history linkage survives reload, while corrupt or duplicated linkage is disabled. Observation requires merchant signature multiplicity decrease, matching live quantity gain and exact money loss. Session tokens, bounded reconciliation and reentrancy guards prevent stale callbacks or notification listeners from issuing a different request.
- `ActionHistory:Record(action,status,details)`, `Page(filter,page,size)`, `Clear()` form a small bounded record model. Records are sanitized, max 100, with session-local unique IDs. The record model never directly issues inventory commands; the History UI delegates to the revalidated buyback domain resolver. History is excluded from configuration export and profile snapshots. Record module import does not create UI or start work.
- `Extras:SetContextMapping(context,profileOrNil)` validates nine canonical contexts and saved profile identity; `ApplyContext()` owns precedence and combat deferral. Missing imported profile references are inert and visible.
- `Tools:Show(tab)` lazily creates one native themed panel. Options and slash commands compose the domain APIs. Geometry uses the canonical anchor validator, clamping and font-derived paged layout.

Example consumption inside the addon: `local preview, err = Rummage.Junk:PreviewRule("q:poor"); if preview then Rummage.Tools:Show("preview") end`. Enabling requires a separate deliberate call to `Rummage.Junk:EnableRule(preview)`; displaying a preview does not authorize selling.

## Verification

The integrated suite has 122 cases (104 prior cases plus 18 followup groups). Stateful inventory fixtures model source/cursor/destination, exact vendor money changes, delayed acknowledgement and rejection. Cases cover reserve aggregation/protected stock, 18-of-30 and 13-of-20 oracles, consent bounds, split failures, concurrency, cursor ownership, truthful history, strict query validation, UI callbacks, atomic maps, fonts 6..24, paging and category content extent. Full native Lua 5.1 gate, TOC and package checks are recorded with delivery evidence; CI also runs the existing lupa backend.

The patch is kept in one integrated PR because the rule, reserve, history and native UI contracts share the same additive DB migration and TOC load graph. Atomic domain, UI and verification/documentation commits remain separately reviewable; an intermediate main branch exposing incomplete workflows would be misleading. The size exceeds the review skill's usual inspection trigger, so final independent review covers every source slice and all verification evidence.

**Historical 1.12.0 observations (not repeated for 1.12.1):** Live client discovery confirmed Forever 1.60.1 build 71037 / Interface 16001; the TOC build declaration now matches that observed target. A live split probe confirmed that Forever holds the original source count locked until placement; cursor acceptance supports that state as well as eager remainder reporting, while post-placement source/destination and sale inventory/money checks remain exact. Two stateful regressions cover deferred source-count success and failed-placement/changed-cursor recovery. Live large-text inspection also exposed fixed-width main window chrome; measured responsive header/action lanes now reserve their content space while retaining saved outer geometry and the default compact layout. Two regressions cover all three windows, narrow widths, callback preservation and default layout restoration. Button sizing uses guarded native unbounded string measurement or one hidden unconstrained same-font probe, with a regression that simulates already-clipped text widths. The context mapping separator uses ASCII for the native font. A live Keep editor check exposed stale preview counts after reserve edits; Save/Remove now invalidate the preview and Enable consent while preserving query text, with a dedicated regression.

No additional standalone library/package boundary is introduced: domain modules are internal to the existing addon and depend explicitly on its host API adapter. Package/static checks establish install payload contents, not actual server behavior. Live protected actions, taint, real acknowledgements and screen-reader behavior require separately observed client evidence.
